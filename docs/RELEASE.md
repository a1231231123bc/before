# Frameago 0.1 — release work

## Implemented in the first slice

- Story creation, editing, categories and search.
- Photo import, native camera integration, dated notes and timeline.
- Durable local storage, schema validation and save-failure recovery.
- Two-photo comparison and PNG export/share integration.
- Six-second 1080 × 1920 MP4 slider export, playable preview, save to Photos and video sharing. [Implementation and checks](VIDEO-EXPORT.md).
- Confirmation before deleting a photo or story.
- Browser end-to-end tests, domain tests, type checking and CI.

The App Store Connect app has Apple ID `6824610218`, saved in the production submit profile. The name `Before` was unavailable, so EAS created the temporary listing name `Before (540c7d)`; the owner selected `Frameago` on 19 October 2026. App UI, exports, and native display-name configuration now use Frameago; saving the new listing name in App Store Connect is still pending. Build `2` contains the old branding, so a fresh production build is required for the new name on the iPhone. Internal testing group `Team (Expo)` includes the account owner. EAS Submit uses a remotely stored App Store Connect key with the `APP_MANAGER` role. Do not commit signing keys or authentication sessions.

The owner needs active Apple Developer Program membership and access to App Store Connect. Enter Apple credentials and two-factor codes directly in the local CLI prompts, never in the repository or chat. Membership enrollment and agreement acceptance are owner actions.

From the repository, using Node 24:

```sh
npx eas-cli@latest build --platform ios --profile production
```

On the first run, authenticate with Apple, choose the intended developer team, and let EAS manage the distribution certificate and provisioning profile. After a successful build, upload that specific build:

```sh
npx eas-cli@latest submit --platform ios --profile production --id <successful-build-id>
```

The matching App Store Connect app and upload credentials are configured. Use the exact successful build ID when submitting; do not confuse the numeric Apple ID with the bundle identifier or EAS project ID.

After Apple processes the upload, add the build to an internal TestFlight group in App Store Connect and install it through TestFlight on the iPhone. External testing has a separate beta review step. Uploading with EAS Submit does not publish the app to the public App Store.

Sources: [Expo iOS submission](https://docs.expo.dev/submit/ios/), [Apple TestFlight](https://developer.apple.com/testflight/), [Apple Developer enrollment](https://developer.apple.com/programs/enroll/).

## Native beta checks

- Confirm iOS/Android priority and bundle identifiers.
- Test on physical devices: picker cancellation, denied/limited permissions, camera, HEIC/large images, full storage, process interruption, native PNG sharing, rotation, safe areas and keyboard.
- Test Android back navigation and recovery when Android kills the picker activity.
- Test MP4 export on physical devices, saving with add-only Photos access, denial/retry, share cancellation, backgrounding, low storage and Instagram import. Measure memory and encoding time on older phones.
- Test VoiceOver/TalkBack, large text and reduced motion; refine comparison gestures on touch hardware.
- Add complete journal backup/import before users entrust irreplaceable photo collections to the app.
- Decide whether Russian localization and dark mode are part of 1.0.
- Build the first signed iOS binary and validate it through TestFlight.
- Review remaining upstream npm advisories and move to compatible patched dependencies.

## Before store submission

- Validate the app name and final identifiers in the target store; availability is not yet checked.
- Publish a privacy policy and support page with the developer’s contact details.
- Complete Apple privacy disclosures / Google Play Data safety based on the final binary and dependencies.
- Create original store screenshots, description, age rating and app icon variants.
- Verify signing, store accounts, tester enrollment and platform-specific review requirements.
- Complete a real-device regression pass and distribute through TestFlight / a Play testing track.
- Submit only after the owner has reviewed the actual build and store listing.

The current milestone is an iOS TestFlight beta. Public App Store release follows the store checklist above.
